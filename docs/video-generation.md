# 视频生成与 2K 工作流指南

本文档介绍 MiniMax Studio 的视频生成模型规格、Files API 云端参考联动、2K 旗舰超分再生成与 Context-IR 提示词增强。

---

## 1. 视频模型与生成模式

通过宿主媒体命令 `media_generate-video` 驱动，支持以下模型与模式：

### 支持的模型
* **`MiniMax-H3`**：旗舰画质视频大模型，支持全部模式（含 2K 再生成）；
* **`MiniMax-H3-Max`**：高运镜复杂度模型，支持除 2K 再生成外的所有模式。

### 六大生成模式
| 模式 ID (`mode`) | 输入素材要求 | 说明 |
|---|---|---|
| `text2video` | 纯文本提示词 | 文生视频，默认比例 16:9 |
| `image2video` | `image`: 单张参考图 | 图生视频（首帧驱动） |
| `last_frame2video` | `image`: 单张尾帧图 | 尾帧生视频（从结尾反推过程） |
| `frames2video` | `referenceImages`: 恰好 2 张 | 首尾帧受控生成（首帧作为起点，尾帧作为终点） |
| `multimodal2video` | 多模态参考数组 | 全能参考（≤9 张图片 + ≤3 段视频 + ≤3 段音频） |
| `regeneration` | 任务 ID 或基础视频 | 2K 旗舰超分再生成（仅 H3 支持） |

## 2. Files API 联动与优雅回落机制

为避免大体积素材（如 10MB 的视频参考）在 Base64 内联进单条 JSON 请求体时突破宿主 32MiB RPC 消息上限，本套件实现了自动的 Files API 云端暂存流：

```
[本地大素材引用]
       │
       ▼ (优先走 POST /v1/files/upload 二进制直推)
[云端 Files API] ───► 返回 mm_file://{file_id}
       │
       ├───► [成功] ───► 以云端轻量引用组装 POST /v2/video_generation
       │
       └───► [网络/接口异常] ───► 触发 warn 记录 ───► 自动回落至 Base64 内联直发
```

* **安全边界**：单文件上传硬上限为 20MB（`MAX_UPLOAD_FILE_BYTES`），超出时在进入网络层前作为硬错误暴露，绝不伪装为回落；
* **透明兼容**：无论走云端引用还是 Base64 回落，宿主 Media Runtime 的 Task ID 派发与流式下载契约完全不受影响。

## 3. 2K 旗舰画质再生成（Regeneration）

针对已有 768P 成片，支持通过两种路径升格为 2560×1440（2K）高清晰度成品：

1. **`source_task_id` 路径**：直接传入前序生成的成功任务 ID，云端直接调取渲染潜变量升级（耗时最短，保真度最高）；
2. **`base_video` 路径**：传入本地已有 MP4 视频素材，先经 Files API 上传后作为基础潜空间输入进行 2K 强化。

## 4. H3-Context-IR 提示词增强工具

模型工具：`minimax_context_ir`

* **定位**：自动将简短粗糙的口语提示词扩写为符合电影运镜规范的双层结构化成稿（分镜细节、镜头运动、光影质感）；
* **工作机制**：异步派发任务，立即返回回执，生成完毕后由套件自动通过 `app/session.start-turn` 唤醒会话并交付成稿；
* **参数联动**：支持同时传入计划时长（`duration`）、画面比例（`ratio`）与分镜参考图，模型将结合素材构图进行针对性扩写。
